## 一、这篇论文到底在讲什么

**一句话**：现在评测「会调用工具的 Agent」的方法，是拿它的工具调用序列去和一条「标准答案序列」做精确匹配；但我们发现真实模型有三种不同的「做事姿态」，而评分器只认其中一种，于是把「姿态不同」误判成「能力不行」，把本来只有 3~5 分的真实差距放大到 2~3 倍。

**展开讲**，分四层：

1. **Ground truth 只有一个姿势。** 每个任务在评测集里都写死了一条 `correct_tools`（标准工具序列）。评分器的 `tool_selection` 这一维，只有当模型调用的工具序列**和这条标准序列一模一样**才算对。

2. **但真实模型有三个姿势。** 我们用 3 个模型、30 个任务、每个跑 3 遍，把轨迹分成四类：
   - **先追问（ask-first / under-execute）**：DeepSeek-Flash、DeepSeek-V4-Pro 的典型姿势，约 40% 的 trial 里它们会先问「您要挂哪个科室/哪天」，一个工具都不调，等用户回话。
   - **标准执行（canonical / exact）**：约 47%，照着标准序列做。
   - **过度探索（over-explore / over-execute）**：MiniMax-M3 的典型姿势，80% 的 trial 里它会多调好几个工具去交叉验证，甚至一次调 13 个工具才给结论。
   - **其他（other）**：少数。

3. **评分器只奖励「标准执行」，惩罚另外两个。** 因为 `tool_selection` 要求精确匹配，所以「先追问」（序列是空的）和「过度探索」（序列多了）都被判 0 分——**尽管这两种做法在真实场景里往往是合理甚至被鼓励的**。

4. **结果：能力差距被「放大」了。** MiniMax-M3 是唯一一个推理模型、过度探索最重，rule 评分器给它打最低分 0.644（对比 flash 0.783 / v4-pro 0.793，差了 0.149）。但这不是纯幻觉——MiniMax 在真实结果维度上确实也弱一点（意图准确率 0.351、事实依据 0.744）。我们做了个消融（§5.5），把「姿态惩罚」一层层剥掉之后，差距从 0.149 收窄到 0.065（收窄约 56%），但**没消失**。所以结论不是「评分器把好的评成差的」（那种是假倒挂，站不住），而是「评分器把 3~5 分的真实差距放大成了 15 分」。

这就是全文最核心、也最能站住脚的论点：**gap inflation（差距放大），而不是 spurious inversion（假倒挂）。**

## 二、创新点（3 个），以及每个的诚实含金量

| # | 创新点 | 是什么 | 含金量 | 会被怎么质疑 |
|---|--------|--------|--------|--------------|
| 1 | **姿态分类学**（posture taxonomy） | 把工具轨迹分成 ask-first / canonical / over-explore 四类，量化三种模型各自占比 | 中低。under/over-execute 的概念学界早就有，不算原创 | 「这不就是 exploration vs exploitation 换个名字吗？」 |
| 2 | **方向性分歧 + 差距放大**（directional disagreement + gap inflation） | 证明 rule 评分器和 LLM 评分器在「过程维」和「结果维」上**反方向**严格：rule 对过程狠、对结果松，LLM 反过来；进而证明过程评分器会系统性放大温和的真实差距 | **最高，也是本文真正的卖点** | 「LLM judge 也有自偏好，你凭什么拿它当参照？」 |
| 3 | **修正框架**（must/optional/none 标注 + 姿态感知评分 + 消融分解） | 把任务标成「必须用工具/可不用/不需要」，只在 must 桶保留过程惩罚；消融把「姿态」和「能力」两个量拆开 | 中。方法实用，但「重新标注 ground truth」本身不新 | 「你为什么不一开始就把 ground truth 标细一点？」 |

**逐条说清楚：**

- **创新点 1 单独拿出来不够。** 姿态分类是描述性的，是手段不是目的。它真正的价值是给创新点 2 提供「三种姿势同时存在」的证据基础。别指望靠这个发 paper。

- **创新点 2 是全文支柱。** 它比「评分器有 bias」这个老生常谈高一个台阶的地方在于：它证明了分歧是**方向性的**（不是两个评分器随便吵，而是各自在特定维度上系统地松/严），并且把「评分器 bias」具体量化为「把 0.04~0.07 的真实差距放大到 0.149，约 2~3 倍」。而且我们很诚实地说「没放大到假倒挂」——这个诚实本身让论点更可信，审稿人挑不出「你夸大了」的毛病。

- **创新点 3 是加分项不是主菜。** must/optional/none 标注 + 姿态感知评分 + 消融，这组东西让论文从「发现了一个问题」升级成「提出了一个可复用的解法」，并且把「开源标注 schema + 评分器」作为交付物——**这才是能不能从 workshop 升到会议/SCI 的关键杠杆**。单有发现会被拒，发现 + 工具就好发很多。

## 三、借鉴了哪些论文，各自的核心点，我们的差异

| 论文 | 它讲什么（核心点） | 我们跟它的差异 |
|------|-------------------|----------------|
| **Chen et al. 2021**（Codex，pass@k） | 提出 pass@k：抽 k 个样本，至少一个成功就算过，用无偏估计 `1 − C(n−c,k)/C(n,k)` | 我们沿用 pass@k，但证明「采样方差」远小于「姿态方差」，所以它不是主因 |
| **Schick et al. 2023**（Toolformer） | 开创「让 LLM 自己学会调工具」的范式 | 背景板，交代范式来源 |
| **Qin et al. 2023**（ToolLLM） | 16000+ 真实 API 的大规模工具评测集，带标准工具序列 | 我们质疑的正是这类 benchmark 的隐含假设：「标准序列」真的唯一吗？ |
| **Li et al. 2023**（API-Bank） | 工具增强 LLM 的评测基准 | 同上，是「单一 ground truth」的代表 |
| **Yao et al. 2024**（τ-bench） | 多轮「工具-Agent-用户」交互评测；**引入 pass^k**（k 次全过才算过） | 我们沿用 pass^k；但 τ-bench 假设任务是单轮可完成的，我们关注「先追问」这种多轮姿势 |
| **Patil et al. 2025**（BFCL，ICML 2025） | 标准化函数调用指标 | 作为「精确序列匹配」现状的代表，我们指出它测不出姿势多样性 |
| **Huang et al. 2026**（SABench，副作用） | 「任务完成 ≠ 做对」，评测「完成了但有害」的副作用 | 我们关心的是「合理但非标准」的动作，SABench 关心的是「完成但做错」的动作——正交 |
| **Zheng et al. 2023**（MT-Bench） | 提出 LLM-as-a-Judge 并用 MT-Bench 验证 | 我们用 LLM judge 作为 rule 的参照系 |
| **Wang et al. 2023**（LLM 不是公平裁判） | 指出 judge 有位置偏差、冗长偏差、自偏好 | 我们承认 judge 有 bias，但主张**ground truth 才是更大的 bias 源**，跟 judge 无关 |
| **Executable-Contract Audit**（arXiv:2609.37315） | 审计评测器本身有没有 bug（oracle audit） | 我们看的是「评测设计有系统性 bias（单一 ground truth）」，不是「评测器有 bug」 |
| **Lightman et al. 2023**（Let's Verify Step by Step） | 过程奖励模型（逐步骤打分） | 我们展示了「过程型 vs 结果型」两种评分在工具场景下**方向性**分歧，对 reward model 设计有启示 |
| **Uesato et al. 2022** | 过程 vs 结果反馈的对比 | 同上，作为过程/结果二分的理论来源 |
| **claw-eval**（我们搭的 harness） | 乘法安全门（safety × mean）、pass@k/pass^k 实现 | 我们直接搭在它上面，所以 aggregate 公式、安全门都是它的 |

**一句话概括差异定位**：别人在「把 ground truth 标得更全、把 judge 调得更准」，我们在问一个更底层的问题——**「标准答案序列」这个前提本身，是不是就错了？**

## 四、能不能发「凑活的」会议 / SCI：诚实判断

**直接说结论：现在的体量，只够投 workshop / short paper，不够投正会或 SCI。**

理由（都是硬伤）：

- **样本太小**：30 个任务、每个 3 遍。optional 桶只有 **3 个任务**（H001-H003），任何基于这个桶的结论都是「方向性证据」，不是「统计结论」。
- **单场景**：只有医院导诊一个合成场景，外部效度（能不能推广到金融/客服/编码）完全没验证。
- **只有 2 个模型家族**：DeepSeek 和 MiniMax。两家族只能「展示现象」，不能「界定现象边界」。
- **没有统计检验**：没有 bootstrap、没有 McNemar、没有置信区间。审稿人一句「你这个 0.149 vs 0.065 的差距，显著吗？」就能问住。
- **没有 head-to-head**：没有直接和 SABench / oracle-audit 的方案在同一个 benchmark 上比。

**但是，如果补齐了，这篇是有机会的。** 它真正的底牌是：

1. 论点**诚实且可辩护**（gap inflation 而不是假倒挂），审稿人挑不出「夸大」的毛病；
2. **消融分解**（§5.5）是实打实的定量方法，不是空口；
3. **方向性分歧**（§5.2）这个观察有增量，不是重复造轮子；
4. 交付物是**可复用的标注 schema + 评分器**，有工具价值。

补齐之后，目标定位应该是：**评测/Agent 方向的会议（CCF-C 级别，或 ACL/EMNLP/NeurIPS 的评测类 workshop 先拿个位置），或者一个普通三区/四区 SCI**。指望一区正会是过高的。

## 五、现在最单薄 / 最牵强 / 最水的地方（按致命程度排序）

1. **【最致命】过度探索可能是 mock 工具的 bug 造成的，不是模型真的爱探索。** 论文 §7 自己也承认了：mock 的 `query_doctor_schedule` 只认字面「周四」，不认「本周四」或完整日期。一个「精确」的模型传了完整日期 → 查不到 → 重试 → 被记成过度探索。这直接**偏向了我们的论点**（对 MiniMax 不利、对「存在过度探索」这个论题有利）。审稿人一眼就能看出这是 artifact。**这个必须量化消掉，否则论文站不住。**

2. **样本量撑不起分桶结论。** optional 桶 3 个样本，任何「optional 桶应该关闭过程惩罚」的说法都是 anecdote。

3. **「姿态」这个核心概念没给形式化定义。** 现在 exact/under/over/other 是「跟 expected 序列比长短」的粗分法，审稿人会问：你怎么区分「合理的过度探索」和「真的乱调」？

4. **两个 DeepSeek 模型既当 agent 又当 judge。** LLM judge 是 V4-Pro，它同时是被评对象之一，自偏好偏差没消除。MiniMax 是交叉了，但 DeepSeek 自己没交叉。

5. **引用里有两个 2026 年的 arXiv ID 待核实**（见第七节），提交前不核实就是事故。

## 七、审稿人最可能打的三枪 + 怎么接

**枪 1：「你的 ground truth 标注太粗，重新标细一点不就好了，不需要一篇论文。」**
接：重标能修「这次」标错，但修不了「先追问到底算不算对」这种**价值判断**——三个模型三种姿势是系统性的，不是偶发标错。而且我们证明的是：只要 ground truth 还是「单一序列」，就必然惩罚其中两种姿势。这不是标注精度问题，是标注**粒度/形式**问题。

**枪 2：「过度探索是你 mock 日期参数脆弱造成的 artifact，不是模型特性。」**
接：这是我们最该提前自己做的实验（P0）。做完之后：如果过度探索率在日期归一化后确实回落，就如实报告、收缩「过度探索」的强度声明；如果没回落，这就是最强反击证据。**无论如何都要先做掉，不能留给审稿人来做。**

**枪 3：「你拿 LLM judge 当参照，但它也有自偏好，你的『差距放大』结论不可信。」**
接：我们用**三方交叉**（rule 评分器、LLM judge、消融重打分）互相印证，LLM judge 不是唯一参照。而且关键结论（gap inflation）主要靠**消融**支撑，不靠 LLM judge 的绝对值。
