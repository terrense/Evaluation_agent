# 1. 研究判断与主线

建议推翻旧稿的中心归因，保留存量轨迹和工具环境作为探索证据。最值得深入的问题是：**评测器放宽对执行路径的限制后，能否接纳真正有效的替代做法，同时继续拒绝与之相近的错误或违规执行？**

英文研究问题：*Can evaluator repairs admit valid alternative workflows without accepting minimally invalid counterparts?*

这条路线有明确测量对象、可控干预、独立可检查标签、强对照和失败条件。原来“某模型多调用工具，因而被规则低估”的论证依赖模型内在倾向的解释、把 judge 当作能力近似，以及受单点强影响的相关性，支撑发表的证据不足。

拟题 **Auditing Tool Agent Evaluators with Certified Trajectory Contrasts**。贡献应落在可执行正负轨迹对、证据与时序条件、修复前后的误判取舍和可复用审计实现。DAG、契约、状态验证或 metamorphic testing 本身已经有扎实前作，不能重新命名就宣称首创。

本次交付包含完整英文论文主干、已执行的离线复核与反例结果，以及未执行部分的确认性研究设计。正式跨域研究没有完成；论文明确区分 completed 和 prospective。这是一版可以继续做研究的完整初稿，尚不具备把新方法写成“已验证有效”直接投稿的条件。

本次未产生新的付费模型调用，未重新生成 6,300 条轨迹。实际运行的是存量重评分、统计复核和 35 条构造诊断。代码审计固定于 commit `1422f412f25fd55a282e4551739a24e7deb3649f`。

# 2. 已有材料的价值与必须修正的问题

## 2.1 可以保留的资产

21 个端点配置 × 100 个任务 ID × 3 次，合计 6,300 条存量轨迹；2,100 条 trial 0 judge。全部 50,400 个规则维度分数重算一致，隔离执行 25 个现有单元测试函数通过。审计使用外部框架分数容器替身，不等于 OpenJudge 集成测试。

任务文件 SHA-256：`0929df5615928b11a98d471d37ef129444e1366f0fec9bc9bdb22a0b9910d352`。100 个 ID 对应 98 个不同输入字符串。12 个配置属于 Qwen 命名组，不能写成 21 个独立模型家族；端点名称也不能认证底层权重版本。

## 2.2 需要撤回或改写的结论

| 问题 | 已检查的事实 | 论文处理 |
|:---|:---|:---|
| 主流 benchmark 都要求唯一序列 | τ 系列状态/沟通检查；ToolSandbox 有灵活依赖 | 删除普遍化批评 |
| 两套分数直接对照 | 规则平均三次，judge 只评第一次 | 主分析逐条配对 |
| overall 聚合一致 | judge 自由生成 overall，规则另有公式 | 另报相同聚合口径 |
| A 是移除过程维度 | 实际设三维为 1，分母仍为 8 | 同报 set-to-one 与 actual removal |
| 相关性说明普遍倾向 | r=−0.788，去掉 M3 后 −0.281 | 作为探索，不做模型本质归因 |
| completion 代表任务完成 | 13 条 max-turns 中 5 条 completion=1 | 用独立目标条件和终止状态 |
| groundedness 全面可信 | 错楼层/错实体仍可满分 | 增加实体、事实、来源绑定 |
| 追问意味着最终成功 | 未实现追问后持续用户交互 | VALID_PENDING 与 COMPLETE 分开 |
| mock 预约代表真实写成功 | 缺持久库存、授权、幂等语义 | 建状态环境再研究写入 |
| 历史日期修复已排除缺陷 | 当前旧/新文件为 300/90 条 | 不保留为可复现配对结论 |

`intent_accuracy` 使用期望工具重叠，`argument_correctness` 很大程度检查未返回错误，`task_completion` 不是完整目标验证。不能依据维度名称就认定八维平均是全面能力测量。LLM judge 也没有完整任务 oracle、系统政策和环境契约，不能自动当作真值。

模型 M3 在 judge 排名同样最低，不应写“judge 中游”。工具次数更多不必然表示探索更认真，无工具调用也不必然表示先追问。单一任务提示、工具版本和预算都有混杂影响。

上游 claw-eval 的安全门控加权逻辑并非本项目八维平均，应区分借鉴来源与自定义实现。已有静态安全示例和三个脚本式跨环境演示，可作为工程背景，不足以支撑动态安全或通用泛化结论。

## 2.3 实际新增的反例实验

七个楼层查询任务 H007、H056–H061，每个构造五条执行。真值来自确定性环境，不涉及诊疗判断。

| 每类 7 条 | 狭义标签 | 原规则均分 | 放宽 D 均分 |
|:---|:---|---:|---:|
| 正确参考 | 有效 | 1.000 | 1.000 |
| 重复授权只读查询 | 有效，成本增加 | 0.875 | 1.000 |
| 最终错误楼层 | 无效 | 1.000 | 1.000 |
| 无最终回答 | 未完成 | 0.750 | 0.750 |
| 查错科室并错误回答 | 无效 | 1.000 | 1.000 |

通过线 ≥0.75，21 条无效构造全部通过。D 消除了重复读取惩罚，却没有解决误放行。重复读取原本也通过，因此这是分数不变性问题，不是已观察到二分类误拒绝。额外读取增加成本可以合理扣效率分，应与正确性分开。

这些例子证明存在缺陷，不估计自然发生率。七个同类错误可能对应同一个缺失检查，不能夸大为七种独立缺陷。下一阶段需要代表性任务、独立标签和真实轨迹。

## 2.4 A 消融为何不能继续支撑原归因

M3 与其他配置均分差：原始 0.14484；三维设 1 后 0.07947；实际删除三维后 0.12736。safety=1 时，设剩余五维均值 R，则 A=3/8+5R/8，天然压缩差异。不能说“约一半差距由评测偏差造成”。B/C/D 同样只是改测量函数，没有真值就不能分解能力与偏差。

规则/判官 Spearman：未配对口径 0.631；共同 trial 0 为 0.603；同 trial、同八维聚合为 0.582。这说明需要研究分歧，但不能直接认定某一方正确。

# 4. 方法定义与关键细节

## 4.1 契约应规定什么

用户目标；允许来源；实体绑定；鲜度；写操作授权范围和先后；禁止持久/瞬时副作用；最终回答；允许追问与完成条件。契约从任务政策编写，不能从参考工具序列倒推。

楼层任务可允许科室目录和导航 API 两种信息来源；需要同实体、当前版本且权限允许。重复纯读正确性不变、成本增大。若任务要求实时核验，删掉唯一查询后碰巧答对仍不合规；若输入已给出有效事实且未要求核验，直接答可有效。两者必须在可见政策中明确。

预约环境新增患者/账户、时段、容量、预约表、授权表和幂等键。记录 pre/post state、是否提交、事件 ID。返回 success 但状态没变，属于工具实现缺陷；报错但已经写入，重试也可能重复创建。固定时钟才能检验“下周一”，不能把不同周都当同一 weekday。

## 4.2 判定、进度与成本分开

PASS：所有硬约束满足且完成。FAIL：已有可证明的硬约束违反。UNKNOWN：记录缺失、实体绑定不明、检查超时或证据不足。不要用其他维度的高分补偿硬失败。

dialogue_status 另设 COMPLETE / VALID_PENDING / FAILED。合理追问但未得到回复是 VALID_PENDING，不是完成；UNKNOWN 是认识不确定性，不是等待用户。另记 calls、tokens、latency、money。若预算本身是要求，事先写入契约；否则成本变化不自动改变正确性。

## 4.3 正负变换矩阵

| 变换族 | 合法替代 T+ 与前提 | 最小违规 T− |
|:---|:---|:---|
| 读取顺序 | 独立读、稳定版本下交换 | 必要授权移到写入后 |
| 冗余读取 | 纯读、授权、鲜度、预算均满足 | 重复非幂等预约 |
| 替代接口 | 同实体、同版本、等价允许来源 | 同 schema 但查询错实体 |
| 已有信息 | 输入已有足够有效证据时省略读 | 删去唯一必需实时证据后猜对 |
| 失败恢复 | 失败未提交，重试成功 | 首次已提交却再次创建 |
| 终态一致 | 不同允许路径达成目标 | 未授权写入后撤销，终态相同 |
| 最终表达 | 相同事实的忠实改写 | 保留风格但改错楼层/日期 |
| 澄清 | 允许提问，用户补全后完成 | 未回复就标完成或缺参强执行 |

先做纯读重复、独立读取换序、错实体/错事实，再做替代来源与授权时序，最后扩展重试和瞬时副作用。不要一次铺满。重复写不能默认等价；工具报错不能默认未提交；前提不足的正变换不得凑入有效样本。

## 4.4 防止标签循环论证

生成器提出候选，沙箱回放证明可执行，独立 oracle 从任务政策检查义务，人工盲审抽样复核。新 grader 不能同时产生它自己的 gold。共享解析可以，共享核心真值函数会使准确率循环。

证书保存任务/世界版本、两轨迹哈希、变换参数、适用条件、保留和打破的义务、证据事件 ID、回放结果、oracle 版本、人工审阅与不确定原因。负例尽量只打破一个主义务，附带错误必须记录。

可以给出条件命题：保留全部硬约束真值与充分证据，则合取判定不变。这是正确实现应有的性质，不是重量级原创理论。难点在于可执行语义和前提认证。通用带替代绑定的图匹配可能需要搜索，不应写线性复杂度；限定规模，超时 UNKNOWN。

# 5. 下一阶段实验：每项对应一个可否证问题

## E0：旧证据冻结与测量修复

立即复现固定版本与 35 条反例；保存旧评分，新增新版本。修复配对 trial、总分口径、A 命名、终止原因与目标完成条件。输出 manifest、输入哈希、重复输入、失败终止表和历史对照。

验收：mismatch=0；21 配置；6,300/2,100；反例数字一致。修复版拒绝错楼层、错实体、空回答，重复纯读仍正确但成本增加。此阶段只是工程验收，不能代表正式泛化。

## E1：先证明变换可信

12 个全新开发家族 × 2 世界=24 实例，最多每实例 3 正/3 负共 144 对。逐条回放，检查实体、值、权限、版本和状态，抽查每类边界。记录适用率、回放成功率、认证通过率、UNKNOWN 和人工分歧。

若正变换常改变真实目标或权限，停止扩大模型试验，先修语义。这些 pilot 家族进入开发集，不进入确认性测试。

## E2：主实验——修复的双向错误取舍

比较 Legacy、A-set1、A-remove、D、强状态+沟通、里程碑/负面条件、新方法及消融、两家 LLM judges。共同任务、共同可见政策、共同证据与固定阈值。

主标准是误拒绝下降，同时误放行增加不超过非劣界限。暂定设计目标可为下降 10 个百分点、误放行增加 ≤2 个百分点，需 pilot 估算功效并在正式测试前冻结。这是设计值，不是已知效果或安全保证。

同时报告 score invariance 和 decision invariance，避免 0.875 与 1.0 都通过却误称分类改善。若只抬高合法轨迹分数，未改善区分无效执行，不能称修复有效。

## E3：机制与强基线消融

一次移除实体绑定、鲜度、授权时序、瞬时副作用、替代证据路径或 UNKNOWN。输入与其他逻辑保持一致。给强状态基线同样完整事件信息，排除只是多看输入而胜出。

重点看终态相同、授权次序不同的负例，及序列不同但义务相同的正例。强里程碑基线已解决就承认，把贡献转向认证资源与审计效率。

增加“观测信息×判定逻辑”交叉对照：终态+回答与完整可信事件两级信息，分别交给强基线和新方法。若两个执行在可见信息上完全相同但真实有效性不同，任何仅依赖该信息的二分类器都不能同时判断正确；等概率一正一负时错误率至少一半。这是基本不可区分性，不是新的理论创新。它提示我们把证据不足与规则不足分开：共同增加事件后两方都改善，是 instrumentation 收益；同信息下新方法更好，才是逻辑收益。不能把多获得日志的优势全部算作新算法。

## E4：独立人工标注与真实轨迹

600 条分层抽样轨迹，双人独立盲审，第三人裁决；另审 120 对变换适用性。包含有效、无效、UNKNOWN 和自然轨迹，保留抽样概率。盲去模型名、grader 分数、预期 mutation 标签。记录 validity、dialogue_status、违反义务、证据、耗时、不确定原因。报告原始一致率及机会校正系数、类别分布和裁决改动。

再生成 40 家族 × 2 世界 × 5 配置 × 5 次=2,000 条真实 rollouts。检查构造缺陷在自然执行中的关联，分开估计自然错误率，不能拿人工平衡集 accuracy 冒充部署发生率。

## E5：跨领域与跨变换泛化

医院行政、零售各自报告，至少留一种变换完全不用来调阈值。家族隔离比随机拆轨迹重要。可选原生 τ²-bench 40×5×3=600 条，结果与改编任务分开。

TRACE、EST 是测试协议，应在相近候选数量和人工预算下比覆盖、认证比例、独立缺陷发现与每个确认缺陷所需时间。不能把它们当 scalar grader 塞进同一个准确率表。

## E6：固定候选池选择效用（可选）

相同候选池由各 evaluator 选一个结果，独立 oracle 判有效完成，报告有效选择率、成本和相对池内最佳有效结果的 regret。统一平局与 UNKNOWN。保持生成模型不变，才能归因到评测。

第一阶段不做新奖励 RL。奖励若还会放过错实体和非法操作，优化会放大漏洞。E2–E4 通过后再研究训练用途。

# 6. 数据、统计与预算

## 6.1 家族拆分

完整目标 160 家族，医院行政 80、零售改编 80，每家族 2 个世界，共 320 实例。先盘点公开数据许可、回放与真正不同的语义；不足时测试前调整，不能改措辞伪造家族。

| 划分 | 家族 | 实例 | 用途 |
|:---|---:|---:|:---|
| 开发 | 40 | 80 | 契约、实现、pilot |
| 校准 | 20 | 40 | 阈值与不确定性策略 |
| 测试 | 100 | 200 | 锁定主要分析 |
| 合计 | 160 | 320 | 每领域 20/10/50 家族 |

测试每实例最多 3 正+3 负，共上限 1,200 对，加 200 基础执行最多 1,400 个不同产物。适用性不足就少做。独立统计单元仍是 100 家族。

在线主预算 2,000 rollouts，扩展原生评测可选 600。API 成本用 20–50 条 pilot 的实际 tokens 与当日价格估算，设置上限和停止开关，不编造金额。CPU 足以承担大部分回放、检查与统计；现有 GPU 优先做受控开源推理，无需为这条主线先上大规模训练。

## 6.2 公平基线

| 基线 | 要求 | 易犯错误 |
|:---|:---|:---|
| Legacy/A/A-remove/D | 保留版本与准确公式 | 偷改后沿用旧名 |
| State + communication | 完整目标状态与必要回答 | 故意只查单字段 |
| Milestone + minefield | 有依据的依赖和违规 | 冒充原生 ToolSandbox 结果 |
| 新方法消融 | 每次只移除一种因素 | 输入和逻辑一起改 |
| 两家 LLM judges | 相同政策、证据、schema、校准 | 不给政策却据此声称方法优越 |

基线可能同样好，这是允许的结局。公开其实现、信息与调参预算，让审稿人判断增量来源。

## 6.3 指标、区间与重复成功率

有效样本的 false rejection、无效样本的 false acceptance 分开。公布 PASS/FAIL/UNKNOWN 全表、覆盖率、条件错误率与转人工负担。不能悄悄丢掉 UNKNOWN。

配对估计按 family 做 cluster bootstrap，同一家族的世界与变换共同重采样。主要比较预先确定，多重比较用 Holm 等校正。端点集合当作固定集合；泛化到全部模型只作探索，并报告留一模型/供应方敏感性。

pilot 估算配对不一致率与家族内相关性，再定样本量。100 个独立单元零错误，单侧 95% 上界仍约 3%；600 个相关变换不能支持 <1%。预算不足以证明 2 个百分点非劣界限，就报区间并缩小结论，不追加挑选数据求显著。

`(c/n)^k` 是全成功概率 plug-in，在 IID 前提下可用 `C(c,k)/C(n,k)`。它不是至少一次成功的 pass@k。n=3、c=2 时前者 plug-in=.296，实测三次全成功=0。温度 0 也不保证完全确定或独立。

# 7. 实施顺序与验收门槛

以下新模块是设计建议，尚未实现。

| 位置 | 改造内容 | 验收 |
|:---|:---|:---|
| real_agent / runner | 终止原因、原始响应、事件 | max-turns 不冒充最终答复 |
| run_multimodel / providers | 完整指纹、served model、参数 | 输入变化不误命中缓存 |
| tools；新增 env_v2 | 状态、幂等、授权、时钟 | 回放一致，回滚留历史 |
| samples；新增 contracts | 家族、世界、可见政策 | 真值不由参考序列倒推 |
| certification | 前提、回放、独立 oracle | 非法正变换被剔除，UNKNOWN 保留 |
| evaluators | 强基线、证据判定 | 失败有事件 ID，成本单列 |
| analysis_v2 | 配对、cluster CI、覆盖 | 原始结果可重建论文图 |

**第 1 周：** E0 与 12 家族 pilot，冻结缓存、修终止与指纹，打通一个“任务—执行—正/负变换—证据—评分”链路。

**第 2 周：** 实现实体、纯读与替代 API，再加预约授权。强状态和里程碑基线同步完成。环境不可信时不批量调用模型。

**第 3 周：** 两领域家族、人工试标、政策修订，确定样本量/预算/阈值，冻结测试。标注不足时缩范围，不能用自动标签冒充独立人工。

**第 4 周：** 正式对照与自然轨迹，保留失败、重试和停机记录。测试后修复另开版本，明确二次研究性质。

**第 5 周：** 完成标注、消融、统计与失败分析。先检查反例，再看均值，防止平均分掩盖缺陷。

**第 6 周：** 用实际结果重写摘要与贡献，把 prospective 替换为已执行方法；整理数据、许可和复现说明，按期刊格式改稿。

六周假设研究负责人、实现执行者和独立审阅者可参与，不是保证工期。人工与契约设计是主要瓶颈。

**停止条件：** 无法认证则缩小变换类；不优于强基线则转审计/资源贡献；误放行超过界限则不称成功；仅构造例有效则限制外推；人工分歧高则先修政策。不要把每个负面结果都改成另一个新模块掩盖。

# 8. 论文如何变成可投稿成果

当前英文稿已有完整引言、近邻比较、方法定义、实际复核、诊断、计划验证、讨论与局限。正式数据完成后，结果顺序应为：认证与标签质量；主错误取舍；强基线；机制；自然轨迹；跨域；成本与失败例。原 21 配置排行榜放次要位置。

正式主图建议：误拒绝—误放行—覆盖；变换×义务错误矩阵；强基线/消融配对差异区间；实际选择效用。当前四图是审计与协议图，不冒充未来正式结果。

“更准确”需要独立标签，“有创新”需要强近邻比较，“可迁移”需要跨域，“低风险”需要可信区间。厚度来自可追溯证据，不来自加长引言或追加端点。

期刊优先匹配评测、软件测试、实证 AI 方法方向。根据最终贡献选具体目标，再核验届时范围与收录；不预承诺 SCI 分区或录用率。
